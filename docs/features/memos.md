# メモ（memos）

## 目的

家のことで思いついた一言を、X に投稿するような手軽さで書き留める。書いたメモはホームのタイムライン（[home.md](home.md)）に、ほかの記録と一緒に書いた時刻の位置で並ぶ。

## 画面

専用の画面は持たない。

- 書く: ホームの右下の追加ボタン（`src/features/memos/components/MemoForm.tsx`。スマホはシート、PC はダイアログ）。本文は 500 文字までのプレーンテキストで、上限を超えては打てず、欄の下に今の文字数を出す（`MemoField`）。本文を打つだけのフォームなので、追加のシートを開いたときも詳細を編集に切り替えたときも、そのまま打てる（入力欄に焦点を当てる）。
- 読む・直す・消す: タイムラインの行を押して開く詳細（`MemoDetailSheet`。状態と操作は `use-memo-detail.tsx`）。書いた人と日時・本文を出し、鉛筆で本文を直し、三点リーダーから消す。直しても書いた時刻は変わらない（タイムラインの位置が動かない）。直す・消すは書いた本人だけで、ほかの人のメモには鉛筆も削除も出さない。書いたメモは送信を待たずにタイムラインへ先に出す。ログイン中のユーザーがまだ手元に無いときも出し、書いた人は取り直すまで空のままにする（レモンの記録と同じ）。メモは書いた人の言葉なので、家族で管理する共有の記録（予定・タスク・立替・レモン）と違って本人のものとして扱う。
- ピン止め: 詳細の三点リーダーの「ピン止め」「ピン止め解除」（閲覧中でも編集中でも同じメニュー）。下の「ピン止め」の規則に従ってホームの一番上に固定される。ほかの人のメモの三点リーダーにはピン止めだけが出る。選んでもシートは閉じない（編集の途中でも打ちかけの本文を失わない）。
- MCP で書いたメモ: タイムラインの行の左の丸は、書いた人（MCP の認可をしたユーザー）の色の上にロボットのアイコン（`SmartToy`）を置き、書いた人の名前の代わりに MCP クライアントの名前を出す（詳細も同じ）。人は丸の色で分かるので、名前の欄は人の言葉か AI の書いたものかを見分けるのに使う。書いた人はトークンのユーザーなので、直す・消すはその人ができる。

## ピン止め

- 絞り込んでいないとき、ピン止めしたメモはホームのタイムラインの一番上（最新の状態のタイルの下、タイムラインの最初の行より上）に固定して出す。出し方は [home.md](home.md#画面)。
- 絞り込んでいるときは、ほかのメモと同じ判定（キーワード・日付の範囲）で出すかを決め、出すなら書いた時刻の位置に置く（ピンは付いたまま）。絞り込んでいるかの判定は `shared/search.ts` の `isFiltered`（条件が 1 つでも入っているか）で、サーバーと画面が共有する。
  - WHY: 絞り込みは「条件に合う記録を探す」操作で、固定の並びを条件と無関係に上に出すと、合わないメモまで結果に見える。
- 並びは書いた時刻の新しい順（`shared/memos.ts` の `sortPinnedMemos`。サーバーの読み出しと画面の先回りが同じ並びにする）。
- ピン止めしても外しても書いた時刻は変わらない。外すと、タイムラインの書いた時刻の位置に戻る。
- ピン止めは誰が書いたメモでもできる。
  - WHY 直す・消すと違って本人に限らない: ピン止めはメモの言葉を変えず、家族で見るホームの並べ方を変えるだけなので、共有の記録と同じに扱う。
- ピン止めはホームの見せ方なので、MCP の読み出し（`read_timeline`）では書いた日にそのまま並ぶ。
- ピン止めは MCP Events（[mcp-events.md](mcp-events.md)）の `memo.changed` で知らせない。メモの言葉（エントリーの中身）は変わらず、ホームの並べ方が変わるだけなので、届いても受け手には何が変わったか分からない。

## データ

`memos`（[data-model.md](../data-model.md)）。本文と書いた人・書いた時刻、ピン止めしたか（`pinned`）、MCP で書いたメモは書いた MCP クライアントの名前（`mcp_client_name`）を持つ。本文の規則（空でない・500 文字まで）は `shared/validation/memos.ts`。

- MCP クライアントの名前の決め方は [mcp.md](mcp.md#組み立て)（`McpContext.clientName`）。
- 名前は書いた時点のものを残し、本文を直しても変えない。WHY NOT クライアントを参照する: クライアントの登録が消えても、誰が書いたかは残したい（レモンの記録の API キーの名前と同じ）。

## API（`server/features/memos/routes.ts`）

| 手続き | 種類 | 内容 |
|---|---|---|
| `memos.create` | 書き込み | 作成。`id` を指定するとその ID で作る（同じ ID の再送は二重に作らない） |
| `memos.update` | 書き込み | 本文を置き換える（入力はメモの `id` と本文）。書いた本人以外は拒む（`FORBIDDEN`） |
| `memos.pin` | 書き込み | ピン止めする・外す（入力はメモの `id` と `pinned`）。切り替えではなく決め打ちで送るので、送り直しても元に戻らない。誰が書いたメモでもできる |
| `memos.delete` | 書き込み | 削除（入力は `id`）。書いた本人以外は拒む（`FORBIDDEN`） |
| `memos.pinned` | 読み出し | ピン止めしたメモ（書いた時刻の新しい順） |

ピン止めしていないメモを読むのはタイムライン（`timeline.get`）だけなので、一覧の手続きは持たない。

### キャッシュと書き込み

- ピン止めしたメモのキーは `['memos', 'pinned']`（`src/features/memos/queries.ts` の `pinnedMemosQueryOptions`）。ホームの画面が絞り込んでいない間だけ購読する。詳細のメニューの文言（ピン止め・ピン止め解除）もこの控えから読む（`useIsPinned`。詳細は開いたときのメモを持つので、その値では古くなる）。
- 書き込みはタイムラインとこのキーの両方を invalidate し（追加はピン止めしていないメモなのでタイムラインだけ）、先回りもサーバーと同じ置き場所に書く（ピン止めしたものはピン止めの並びにだけ、ほかは絞り込んでいないタイムラインにだけ。`applyMemo`）。絞り込んだタイムラインは、どの書き込みでもほかの記録と同じく控えから除いて取り直しに任せる（[home.md](home.md#キャッシュと書き込み)）。ピン止めしたメモはタイムラインに無いので、編集の前の値はピン止めの並びから先に探す。

## MCP ツール

`add_memo`, `update_memo`。MCP で書いたメモは、出力の `via` に書いた MCP クライアントの名前を持つ。読むのは `read_timeline`、消すのは `delete_entry`（[mcp.md](mcp.md)）。
