# カレンダー（calendar）

## 目的

予定とタスク（[events.md](events.md)）を暦の上に並べて見せる画面の feature。データは持たない。予定とタスクの書き込みはすべて `events` の API に送り、サーバーの `server/features/calendar/` は画面が読む 1 期間分（項目・祝日・天気）をまとめて返すだけ。祝日（[holidays.md](holidays.md)）と天気（[weather.md](weather.md)）は、それぞれの feature が取ってきて保存したものを読んで日付の横に出す。

予定を他のカレンダーアプリで購読するための ics 配信は [calendar-feeds.md](calendar-feeds.md)。

## 画面

| 画面 | パス | 内容 |
|---|---|---|
| カレンダー | `/calendar?view=month\|week\|day\|list&date=YYYY-MM-DD`（リスト表示の絞り込みは `from` / `to` / `kind`=`event\|task` / `participant`=ユーザー ID / `completed`=`open\|done` / `q`。どれも省けば絞り込まない） | 予定とタスクを 1 つの画面で、月（グリッド）・週／日（タイムライン）・リストの 4 通りに表示し、追加・編集・削除する。`view` が無ければ最後に開いた表示（端末の localStorage に覚える。初めては月表示）で、タブを行き来しても好みの表示のまま開く。 |

表示は AppBar 右端のメニューで切り替える。すべて `CalendarItem[]` だけを読み、予定とタスクの差は描画と操作（完了の有無）にのみ現れる。部品は MUI で自作（`src/features/calendar/components/`）し、汎用カレンダーライブラリは使わない。週の始まりは月曜。

- **月**（`MonthGrid`）: Google カレンダー流のレーン配置。週ごとに、複数日・終日の予定を「開始列と長さ」の順に 1 本のバー（開始日・終了日だけ角丸。角は時間軸のブロック・下書きの枠と同じく、ホームのタイルと同じ超楕円でなめらかにつなぐ形で、大きさは `item-shape.ts` の `ITEM_CORNER`）として先に置き（上下のレーンの帯とは繋がって見えないよう、項目の側で上下を 1px ずつ縮める。`LANE_ITEM_HEIGHT`）、残りの日ごとの項目（時刻付き予定は「● タイトル」、タスクはチェック印付き）を空いたレーンに詰める（`lane-layout.ts`）。行の高さに入りきらないレーンは「+n」（`foldLanes`）。完了したタスクは日ごとに一番後ろへ回し（`completedLast`）、「+n」に先に入るようにする。グリッドは画面の残り全部を占め、レーン数は行の高さから実測する（`use-month-grid.ts`）。項目をタップ・クリックすると詳細（`ItemDetailSheet`）が開き、日表示へはスマホなら項目に掛かっていない所のタップ、PC なら日付の数字から移る。セルをなぞると終日の予定を追加できる（PC は空いている所のクリック、スマホは長押しから。タップは日表示に譲る）。出ている枠に掛かるセルを押したときは、選び直さずにその枠をつまむ。枠は終日でも時間指定でも帯で出す（時間指定はその日 1 日ぶん）。保存済みの予定も長押しでつまむと編集モードに入り、同じ指のまま別の日へ動かせる（下記「予定を長押しして直す」）。
- **週・日**（`TimelineView` = `TimelineHeader` + `AllDayRow` + `TimeGrid`）: Google カレンダーと同じタイムライン。上に日付の見出しと終日欄（終日・複数日の予定、時刻の無いタスク。月と同じレーン配置）、下に 0〜24 時の時間軸（`TimeGrid`。縦にスクロールする部分）。時間指定の予定は開始〜終了の高さの塗りブロック、時刻付きのタスクはその時刻に薄い背景の小さなブロック。タスクの時刻は一覧と同じ `taskTime`（完了 → 開始 → 期限の優先。`timelineSlot`）で、置かれた日の時刻でなければ終日欄に出す。同じ時間帯に重なる項目は横に並べる（`timeline-layout.ts`: 終日欄と時間軸への振り分け（`partitionTimeline`）と、重なり合う集まりごとに列を割り当てて幅を等分する配置）。今日の列には現在時刻の赤い線。縦の位置を合わせるのは最初に出したときだけ（月表示から来たときは予定がなるべく全部見える位置: 一番早い予定から一番遅い予定までが画面に収まるなら画面の真ん中、収まらないなら一番早い予定の 1 時間前を一番上。予定が無いときと、月以外から来たときは、今日なら現在時刻の少し上、それ以外は 7 時）で、日付を移っても見ていた時間帯を保つ（`use-timeline-scroll.ts`）。2 本の指でつまむと 1 時間あたりの高さが変わり、時間軸が縦に伸び縮みする（`use-pinch.ts` / `use-hour-zoom.ts`。下記）。週表示で日付の見出しをタップすると日表示へ。空いている所をなぞると時間帯（15 分刻み、最短 30 分）、終日欄をなぞると日（終日の予定）を選んで追加できる。時間軸の枠はつまんで直せる（端で開始・終了、枠そのもので長さを保ったまま移動。週表示では左右に動かして別の日へ持っていける。端はスマホなら丸、PC なら上下の線のどこでも）。保存済みの予定も長押しでつまむと同じ枠になる（下記「予定を長押しして直す」）。終日欄の帯は月表示と同じ見た目で、丸は出さずにセルからつまむ。終日の予定も長押しでつまむと編集モードに入る。
- **リスト**（`ListView`）: 時系列の一覧（Google カレンダーの「スケジュール」）。上が古く下が新しい無限スクロール（`src/lib/ui/InfiniteScroll.tsx`）で、最初は表示中の日（既定は今日）を一番上に出す。その日は項目が無くても「予定なし」として出す。上下の端へ近づくと前後の月を 1 か月ずつ読み足し（`use-list-months.ts`。月を取得し終えてから広げる）、月ごとに見出しを立てる。AppBar に検索、絞り込みボタンで期間・種別（予定／タスク）・参加者・完了状態を開き、絞り込みのフォームは一覧の上に貼り付く。期間を入れるとその外へは広げない。絞り込みを変えると表示中の日の位置へ戻る。
- **状態**: 表示・日付・絞り込みは検索パラメータ（スキーマと絞り込みの規則は `search.ts`。選択欄の値の型もスキーマから導く。`use-calendar-page.ts` がそこから期間・見出し・前後の移動を導き、ページは描画だけ）。表示や日付の切り替え（表示の選択、日のタップ、選択ダイアログ、今日）は履歴に積み、戻るで前の表示に戻れる。スワイプでの前後移動と絞り込みの入力は履歴を置き換える。どちらも入力中の下書き（下記）は閉じない（[ui.md](../ui.md#ダイアログと履歴)）。URL に載せない状態（打ちかけのキーワード、時間軸の高さ）も `use-calendar-page.ts` が持つ。追加の入口（追加ボタン・PWA のショートカット・ほかの画面の追加ボタン）と、予定の入力を閉じたときの戻り先は `use-calendar-add.ts` が持つ。画面の状態を探す所を 1 か所に保つため。キーワードは URL を置き換えるだけにする（`src/lib/search.ts`）。
- **移動**: AppBar の見出し（月なら年月、週なら期間、日なら日付）をタップすると選択ダイアログ（`DatePickerDialog`）。見出しが指す単位と選べる単位を揃え、月表示は年を ‹ › で送って 12 か月から、週・日表示は月を ‹ › で送って月グリッド（月表示と同じ 6 週）の週の行・日から選ぶ。選んだ範囲が今日を含むときは今日へ移る（「今日」が選ばれている見え方に揃える）。月・週・日の表示は左右にスワイプすると前後の月・週・日へ。前後ボタンは置かない。「今日」ボタンで今日へ。
- **スワイプ**（`SwipePager`）: 前・今・次の 3 面（`CalendarPane`）を横に並べた横スクロール + スクロールスナップ。指への追従・慣性・吸着はブラウザに任せ、吸着し終えた面（`scrollend`）が中央でなければ日付を移して中央に戻す。面ごとに自分の範囲を読むので、スワイプした先の予定も先に読み終えている。日付の移動は router の遷移なので、その描画が終わるまで面を中央に戻せず、戻るまでは端に張り付いて続けてスワイプしても動かない。そこで 1 回の移動で描き直す量を減らしてある: **面の key は受け持つページ**（代表する日）にして、1 つ進んでも変わらない 2 面は React がそのまま使い回す（key を位置にすると 3 面とも中身が入れ替わって全部描き直しになる）。**面（`CalendarPane`）は `memo`** で、props（表示と代表する日）が同じなら描き直さない。期間は代表する日から面の中で組み立て（`periodOf`）、渡す関数はページ側で固定する（毎回別の値・別の関数だと使い回しても描き直しになる）。**中身を描くのは表示中の面と既に描いてある面だけ**で、新しく要る端の 1 面は次の描画（transition）で足す（枠となる 3 つの箱は中身の有無に関わらず並べたままにして、横スクロールの寸法と中央に戻す計算を変えない）。これで移動そのものの描画は空になり、中央へすぐ戻れる。足す描画も transition なので、描き終わる前に次のスワイプが来たら捨てて描き直す。表示中の面だけは必ずその描画で描き切る（View Transition が切り替え直後の描画を撮るため。下記）。日付の移動では router のスクロール位置の復元を止める（`resetScroll: false`。復元されると中央に戻した面が元の位置へ引き戻され、スワイプ 1 回でページが延々と送られる）。中央以外の面は `inert` + `aria-hidden`（フォーカスが入ると勝手にページが移るのと、同じ項目が読み上げや自動操作に重複して見えるのを防ぐ）。縦にスクロールする時間軸は横に動かすたびに 3 面で位置を揃える。縦スクロール・横スワイプの切り分けもブラウザのスクロールに任せる。
- **拡大縮小**（`use-pinch.ts` + `use-hour-zoom.ts`）: 週・日の時間軸を 2 本の指でつまむと、1 時間あたりの高さが指の間隔と同じ倍率で変わる（24〜240px）。渡すのは始めた時点からではなく直前からの倍率なので、受け取る側は上限・下限で止めるだけでよい（始点からの比だと、止まったあとも比が伸び続けて戻すときに効かない時間ができる）。高さは小数のまま持ち、渡すのは整数に丸めた値にする（指をゆっくり動かしたときの僅かな倍率も積もって効き、渡す先から見れば高さは整数しか取らないので、同じ高さの間は面を描き直さずに済む）。**1 時間の高さはグリッドに CSS 変数（`--hour-height`）で置くだけで、時間軸の中の寸法（時刻の目盛り・1 時間ごとの罫線・予定のブロック・下書きの枠）はすべてそこからの `calc` で決まる**（`use-hour-zoom.ts` の `atMinute`）。伸び縮みで変わる値は 1 つなので、指に合わせて何十もの寸法を JS で組み直さず、その数だけ使い捨ての CSS が作られることもない（つまむ前後で増える CSS 規則は 100 フレーム動かしても数個）。**px を組み立てるのは CSS だけ**で、JS が高さの数を持つのは CSS 変数へ渡す所と、伸び縮みを察してスクロール位置を合わせ直す所だけ。なぞったときの分は列の高さ（＝1 日）に対する割合から（`use-time-drag.ts`）、最初の縦位置と枠を見える所へ送る判断は時間軸の `scrollHeight` から引く。ブロックに時刻の行を添えるかどうかも `@container (min-height: …)` で決めるので、同じ寸法の規則が JS と CSS に二重に書かれる所は無い。高さの状態はカレンダー画面に 1 つだけ置き、スワイプの 3 面すべてに同じ値を渡す（面ごとに持つと、拡げたあとスワイプした先だけ元の高さに戻る）。伸び縮みしたら画面の真ん中に見えていた時刻をそのままの位置に残す（上端を固定すると、拡げるたびに見ていた時間帯が下へ流れていく）。3 面が同じだけ動くので縦位置は揃ったままになる。つまみ始めたら 2 本とも自分でポインタを受け取り（`setPointerCapture`）、タッチの既定の動きを止める（2 本指はブラウザにとってスクロールなので、止めないと拡げ縮めと同時に画面が流れる。止め方は範囲選びと同じ `touch-block.ts` の 1 か所に置く）。1 本だけのスクロール・なぞりはそのまま通す。別の指が触れたら範囲選び（下記）はやめてこちらに譲る。ブラウザ自身の拡大縮小は全画面で止めてあり（`touch-action: pan-x pan-y`。[ui.md](../ui.md#タッチ操作)）、つまむ操作が効くのはこの時間軸だけ。
- **表示の切り替え**: 月・週・日・リストを切り替えると View Transition で繋ぎ、両方の表示に在る項目はその場から新しい位置へ動く（それ以外はフェード）。項目の名前は `item-transition.ts` が発生（繰り返しの 1 回）ごとに決める。名前は文書の中で一意でなければならず重複すると遷移そのものが行われないので、同じ発生が複数描かれる所は 1 つに絞る: 複数日の予定は初日だけ（月グリッドは週の行ごとに帯が分かれ、リストは日ごとに行が並ぶ。続きの日はフェード）、スワイプの控えの面（`inert`）は対象にしない（`src/lib/theme.ts`）。遷移の前後として比べられるのは切り替え直後の描画なので、**表示中の面の項目はその描画に載っていなければならない**（あとから足される物は動かずに出るだけになる）。前後の面は `inert` で対象外なので、要るのは表示中の面だけ。日付だけが変わる移動（スワイプ・今日・選択ダイアログ）では遷移しない。
- **色**: 項目は参加者 1 人ずつの色で塗り分ける（`src/features/events/use-participant-colors.ts`、[users.md](users.md)）。誰もいない項目は無彩色。帯・時間軸のブロックは面ごと塗り分け（`src/lib/ui/wedge.ts` の `wedgeBackground`。2 人は / の斜め、3 人は左上と右上の角へ開く Y の字、4 人は十字）、文字は境目をまたいでも読めるよう 1 色（`shared/color.ts` の `FILL_TEXT`）。時間軸のタスクは同じ塗り分けを薄い色（`tint`）にし、チェック印を添える。まだ保存していない下書きの枠も同じ規則で、選んでいる参加者の色で線を塗り分ける（線は淡い `fill` では背景に埋もれるので、濃い `line`）。
- **高さ**: 月・週・日の表示は画面の残り全部を占める（`AppShell` が下に確保する余白は負のマージンで打ち消す。高さの基準は `svh`。[ui.md](../ui.md#レイアウトとナビゲーション)）。
- **詳細**: 項目をタップすると予定・タスクの詳細（`ItemDetailSheet`。[events.md](events.md#詳細)）が開く。リスト表示の行は長押しでその入力欄から開く（アプリ全体の「単押しは閲覧、長押しは編集」）。グリッドの長押しは詳細を開かず、その場でつまんで動かす（下記「予定を長押しして直す」）。
- API 上は複数日の予定が日ごとに 1 件（`dayIndex` / `dayCount`）で返るので、グリッドとタイムラインの終日欄はそれをバーに束ねる。リスト（`DayList`）では日ごとの行のまま表示する。

## グリッドから予定を追加する（下書き）

Google カレンダーと同じく「範囲を選ぶ → その場で入力 → 保存」で追加する。選んだ範囲（まだ保存していない予定）を **下書き**（`draft.ts` の `DraftRange`。時間指定か終日かの 2 通り）と呼ぶ。予定の入力の状態（グリッドの下書きとクイック入力／「その他のオプション」で移した全項目のフォーム／どちらも無い）は `use-event-composer.ts` が 1 つの値で持ち、変えるのは `composerReducer` だけにする（ページは操作を並べるだけ）。下書きとクイック入力、全項目のフォームは同時には開かず、それを型（`mode` で分かれる 1 つの値）で守る。グリッドの面へは下書きを 1 つの値（`GridDraft`）のまま渡し、枠の色・なぞり終えたかは面の中でそこから読む。選んでいる参加者も下書きの一部として持つ: 枠の色（`useParticipantColors`）とクイック入力のチェックボックスが同じ値を見るので、参加者を変えると枠の色もその場で変わる。既定は自分だけで、枠を動かしても選んだ参加者は持ち越す。

1. **選ぶ**: グリッドをなぞる（`use-range-drag.ts`。ドラッグ 1 回の進み方（長押しの待ち → 掴む → 範囲を知らせる）は React から切り離した `range-drag-session.ts` の状態機械が持ち、フックはそれを要素のハンドラと描画の寿命に繋ぐだけ）。マウス・ペンは押した時点から、タッチは長押しから始め、タップや縦スクロール・横スワイプと分ける。1 つのドラッグは 1 本の指だけのもので、別の指が触れたらそのドラッグは終わる（時間軸ではそれがピンチの始まり）。別の指がどこに降りるかは選べないので、掴んだ要素ではなく文書全体で見る。時間軸はタップでも選べて 1 時間になる（月表示のタップは日表示に譲り、項目の上のタップは詳細に譲る）。時間軸は 15 分刻みに吸着し（`use-time-drag.ts`）、月表示と終日欄は日単位（`use-day-drag.ts`）。範囲が変わるたびに震えて区切りを指に返す（`useRangeDrag` の `vibration`。長さを決める規則は `time-draft.ts` の `timeVibration` と `day-draft.ts` の `dayVibration` に置き、汎用のドラッグは時刻や日の意味を知らない）。範囲は state に持たずページに渡し、描画は下書きの枠（`DraftBlock`）に任せる。ドラッグは「何をつまんだか」（`time-draft.ts` の `TimeGrab` / `day-draft.ts` の `DayGrab`。空いている所なら null）と押した所・今の所の組（`Drag`）で表し、そこから範囲を出す計算は `timeDraft` / `dayDraft` に閉じる（下書きの形と項目 → 枠は `draft.ts`、下書き ↔ フォームの値は予定が `event-draft.ts`・タスクが `task-draft.ts`）（`use-range-drag.ts` は掴んだ物の意味を知らない）。
2. **調整する**: 出ている枠はつまんで直せる。選び直しでもつまんで動かしたときでも、範囲が変わるたびに震える。表示を切り替えても下書きは残り、切り替えと同時に下書きの初日（複数日なら最初の日）へ移るので、月で日を決めてから週・日で時間を詰める、といった直し方ができる。移らずに見ていた日のままだと、下書きが画面の外に出て見失う（月表示で選べる日は、週・日の表示が一度に出せる日より多い）。日付そのものを動かす移動（「今日」・スワイプ・日のタップ・選択ダイアログ）は行き先を名指しした操作なので、下書きは連れていかない（下書きが画面から出るのは求めた通りの結果）。表示の切り替えだけが、同じ日を見ているつもりのまま出せる期間の広さを変えるので連れていく。
   - **時間軸（週・日）**: 枠の端をつまむと開始・終了だけが動き、反対の端は越えられない（15 分だけ残す）。丸以外の枠をつまむと長さを保ったまま動く。どちらも押した時点から動き出す（長押しは待たない。枠は「今つまんでいる予定」なので、そこに触れるのは直すときだけ。縦スクロールと横スワイプは枠の外から始める）。端はスマホでは丸（8px。指の当たりだけ 32px に広げる）、PC では上下の線のどこでも（載せるとカーソルが上下の矢印になる）。PC は指で狙わないので印は要らず、Google カレンダーと同じく線そのものを掴む。どちらも一番近い 15 分に吸着する。震えの長さは吸着した時刻で決まり、正時は 50ms と長く、15・30・45 分は 10ms と短くして、時間の区切りを見ずに分けられるようにする。基準は動いた側の時刻で、枠ごと動かして両方が動くときは開始時刻。日が変わるのは枠そのものを動かしたときだけで、週表示で左右に動かすと指の下の列の日へ移る（端と、空いている所からの選び直しは始点の日のまま）。枠は列の中ではなく列に重ねて置き（そのため時間軸のグリッドは子の置き場所をすべて明示する）、日が変わっても同じ要素のまま列を移る。列の中に置くと日ごとに要素が入れ替わり、掴んでいた要素が DOM から消えた時点でタッチが途切れて横スワイプに化けてしまう。枠はポインタを受けるので、枠の中から選び直すことはできない（空いている所から選び直す）。
   - **日の並びの帯（月表示、週・日の終日欄）**: 帯は丸も出さず、ポインタも受けない見せるだけのもの（`DraftBar`）で、つまむのは下の日のセル。押したセルが最初の日の左半分なら開始、最後の日の右半分なら終了、それ以外の掛かっている所なら帯ごと（日数を保ったまま）動かす（`dayGrab`）。ここも時間軸と同じく押した時点から動き出す（長押しを待つのは空いている所からの選択だけ。帯に掛かる所を押すのは直すときだけなので、日表示へのタップや横スワイプは帯の外から始める）。帯そのものを押す作りにしないのは、帯が指より薄い（月グリッドで 17px）ため狙って押せず、月グリッドでは週の行ごとに帯が分かれていて、行をまたいで動かすと掴んだ要素が DOM から消えてしまうため。端は反対の端を越えられない（1 日だけ残す）。月グリッドで下の行へ動かせば 1 週間ぶんずれる。震えは日をまたぐたびに 10ms で、区切りが 1 種類しか無いので長さも 1 つ（長い 50ms は時間軸の正時だけの合図に取っておく）。
     月グリッドには時間指定の下書きもその日 1 日ぶんの帯で出す。日の並びでは時間帯を変えられないので、つまめるのは帯そのものだけで、時間帯を保ったまま日が動く（時間帯は週・日の時間軸で直す）。週・日の終日欄には終日の下書きしか出さない（時間指定はそちらの時間軸に枠で出るため）。
   - Vibration API の無いブラウザ（iOS）では震えは何も起こらない。PC は吹き出しを開いたまま時間軸の枠をつまめる（下の「PC」）。月・終日欄の帯はセルからつまむので、吹き出しの外を押したことになって下書きが消える。選び直すかその他のオプションで直す。
3. **入力して保存する**: クイック入力（`components/QuickItemForm.tsx`。状態と下書きとの同期は `use-quick-form.ts`。入れ物（スマホのシートと PC の吹き出し）と項目は予定とタスクで同じ `components/QuickForm.tsx` で、違うのは上の段に出す日時と通知の項目（`kind`）だけ。下書きからしか開かないのでカレンダーの部品。組み立てと検証は予定のフォームと同じ `useItemForm`）。上端の帯の真ん中で予定とタスクを切り替えられる（下記「予定とタスクの切り替え」）。保存すると一覧を取り直し、予定がその場に出て下書きは消える。開く段は入口で決まる: グリッドからは下の段、追加ボタンからは上の段（全項目）。
   - **スマホ**: 画面下のシート（`src/lib/ui/BottomSheet.tsx`）。ダイアログには移らず、同じシートの見える量だけが変わる。下の段はタイトル・日時の見出し・参加者だけ、上の段（画面いっぱい）は全項目（終日・開始・終了・場所・メモ・繰り返し・通知）。項目はどちらの段でも DOM にあるので、どこまで広げていても同じ 1 つの `<form>` として保存できる。上の段で日時を直して下の段に戻ると、その日時を下書きに映してグリッドの枠と見出しに反映する（日をまたぐ時間指定など枠に出せない範囲だけは枠をそのままにする）。終日かどうかも下書きだけが持ち、「終日」の切り替えは下書きそのものを切り替える（時間指定からはその日 1 日、終日からは最初の日の既定の時間帯。`draft.ts` の `withAllDay`）。入力の側にも持つと、シートを開いたままグリッドで別の種類の枠を選び直したときに、見出しと保存する日時が食い違う。
     - シートは `BottomSheet` を上・下の 2 段で止める使い方（`peekRef`。仕組みは [ui.md](../ui.md#ボトムシート)）。指に追従して動き、離すと動かした向きへ 1 段ぶん進む（40px 以上動かしたときだけ。それ以下なら元の段に戻る）。下の段からさらに下げると閉じる。モーダルにしないので、下の段では後ろのグリッドをそのまま触れる（枠の端をつまんで時間を直せる）。上端の帯（閉じる・保存）は `RecordSheet` と同じ `SheetHeader`。
     - キーボードに隠れないよう、`index.html` の viewport に `interactive-widget=resizes-content` を指定している（キーボードが出たら表示領域自体を縮める）。
   - **PC**: 下書きに寄せた吹き出し。タイトルと参加者だけを扱い、足りない項目は「その他のオプション」で入力済みの内容ごと全項目のフォーム（`ItemForm`）へ渡す。直している予定も一緒に渡すので、そちらで保存しても同じ予定の上書きになる（見出しと繰り返しの扱いもそれに合わせる）。吹き出しの外を押すと下書きを捨てる（グリッドを押しても閉じるだけで、新しく選び始めない）。吹き出しはモーダルにしないので、開いたまま時間軸の枠をつまんで直せる。なぞっている間は枠に重ならないよう隠し、離したら枠の新しい場所に寄せ直す。入力途中のタイトルは残る。
   - 全項目の並び（日時・場所・メモ・繰り返し・通知）は `EventFields.tsx` に切り出し、全項目のフォームとシートで同じものを使う。値の組み立ても `itemInputFromForm`（`form-values.ts`。予定・タスクで 1 つ）で共通にし、フォームが増えても項目とキーがずれないようにする。

## 追加ボタンから追加する

右下の追加ボタン（`AddFab`）は 1 つで、見ている日に終日の予定の下書きを置き、グリッドからの追加と同じ流れに合流する。

- タスクにするなら入力の上端で切り替える（下記「予定とタスクの切り替え」。開始の日だけを引き継いだ終日のタスクになる）。種類を選んでから開くより、書きながら決められるほうが手数が少なく、予定とタスクのどちらで入れるか迷ったまま書き始められる。
- 追加ボタンからは時間帯を選んでいないので、決め打ちの時間帯を置くより日だけを決めておくほうが直す手間が少ない（時間帯を選びたいときはグリッドをなぞる。「終日」を切ると次の正時から 1 時間になる。`withAllDay`）。
- 週・日表示ではその表示のまま終日欄に置く。月・リスト表示では「終日」を切ったときの時間帯が見えないので、入力を閉じるまで（保存でも取り消しでも）日表示を出し、閉じたら元の表示に戻る（`previewDay`。URL の表示は変えない）。入力中に自分で表示を切り替えたら、閉じてもその表示のまま。
- ホームの追加ボタン（`AddMenu`。予定・タスクを別々の項目として出す）から予定を選んだときはカレンダーへ送り（`useAddEventOnCalendar` が `add=event` を付けて移る。追加ボタンは選ばれた種類を画面へ渡すだけで、移動は持たない。しるしは使ったらすぐ消す）、最後に開いた表示で同じ流れになる。
  - 入力を閉じたら（保存・取り消し・戻る操作のどれでも）ホームへ戻る。ホームの追加ボタンから始めた操作はホームで終わるように。入力中に表示や日付を切り替えて履歴を積んでいても、閉じるとそれごと越えてホームへ戻る（来たときの履歴の位置を覚えて渡る。`traverseTo`）。
  - 印は履歴の state（`RETURN_ON_CLOSE`）にあるので、前の画面が無い PWA のショートカットや再読み込みでは付かず、カレンダーに留まる。
  - ホームのほかの種類（タスク・立替・レモン）はホームの上でフォームが開くので、元からホームのまま。
- 下書きの間は追加ボタンを引っ込める（クイック入力と場所が重なるため）。
- PWA のショートカットも同じ入り口に来る（予定は `add=event`、タスクは `add=task` で、タスクは初めからタスクの下書きで開く。[architecture.md](../architecture.md#pwa)）。

## 予定を長押しして直す（編集モード）

保存済みの予定は、**長押しでつまむと編集モード**に入る（グリッドでの「長押しは編集」はこれで、詳細のシートは開かない）。つまんだ予定はその場で下書きと同じ枠（時間軸なら `DraftBlock`、日の並びなら `DraftBar`）になり、**指を離さずにそのままなぞれば**長さ（時間軸なら時間、日の並びなら日数）を保ったまま動かせる。離した後も編集モードのままで、枠は長押しを待たずに動く。入力は追加と同じクイック入力（`QuickItemForm`）で、既定値がその予定の内容（タイトル・場所・メモ・繰り返し・通知）になるだけ。保存すると同じ予定を上書きし、シートを閉じれば何も変えずに終わる。

月・週・日のどの表示でも操作は同じで、直せる範囲だけがその表示で見えているものに従う（時間軸では時間帯と日、日の並びでは日）。表示を切り替えても編集は続くので、月で日を決めてから週で時間を詰める、という直し方ができる。

- 枠と「直している予定」は 1 組（`draft.ts` の `Draft`）で扱い、上の入力の状態（`use-event-composer.ts`）が 1 か所で持つ。ドラッグは範囲と対象を一緒に返すので、つまむたびに何を直しているかが決まる（空いている所をなぞれば対象は無くなり、新しい予定の下書きになる）。
- 保存の宛先は対象だけで決まる: 対象があれば上書き（`useUpdateEvent`）、無ければ追加（`useCreateEvent`）。入口（クイック入力／その他のオプション）では変わらない。繰り返しの回は「この回だけ」を直す（つまんだのはその回で、ほかの回の日時まで動かさないため）。範囲の決め方は `grabbedScope` 1 か所に置き、保存の指定と入力欄の出し分け（繰り返しの設定は触らせない）が食い違わないようにする。
- 編集中の予定は枠で出すので、元のブロック・項目は**隠すが DOM からは消さない**。長押しでつまんだ要素が消えると、その場でタッチが途切れて指を離さずに動かせなくなる（横スワイプに化ける）ため。隠すのは `visibility` で、場所（レーン・列）はそのまま残す。同じ発生かどうかは暦日ではなく種別・id・繰り返しの回で見る（`shared/calendar.ts` の `occurrenceKey`。複数日の帯を束ねる所・表示の切り替えで動かす名前も同じ鍵を使う。複数日の予定は日ごとに 1 件で、月グリッドでは週の行ごとに帯が分かれるため）。
- 軽いタップは項目自身のものにする（どの表示でも詳細（`ItemDetailSheet`））。ドラッグ（`use-range-drag.ts` の `tap: false`）は、動かさずに離したときは何も選ばずタップを項目の click に譲り、クリックかもしれないうちは知らせない。項目に掛かっていないセルのタップは今までどおりで、スマホの月表示なら日表示へ移る。
- つまめるのは枠に出せる項目だけ（`itemDraft`）。日をまたぐ時間指定の予定は枠で表せないのでつままない。タスクは下記「タスクを長押しして動かす」。時間軸は指で触れるスマホだけ（PC はクリックで開く詳細から直す）、日の並びは PC でも同じようにつまめる。


## タスクを長押しして動かす

タスクも予定と同じく**長押しでつまむと編集モード**に入り、同じ指のまま動かせる。枠はタスクが置かれている所で、時間軸なら置かれた時刻（`taskTime`）の最小の長さ（30 分）のブロック、終日欄・月表示なら置かれた日 1 日の帯（`itemDraft`。時間軸の置き方 `timelineSlot` と同じ規則なので、置いた所をそのままつまめる）。タスクは長さを持たないので枠は動かすだけで、時間軸の端の丸・線は出さず、日の並びでも端はつままない（`dayGrab` はどこを押しても帯そのもの）。完了したタスクは完了した日時に置かれていて、開始・期限を動かしても場所が変わらないのでつままない。

動かした結果は `task-draft.ts` の `taskTimesAt` 1 か所で決める。枠を動かす元になるのは、下書きが持つタスクの日時（`GridDraft` の `task` = `TaskTimes`。開始・期限・終日かと、それが置かれていた枠）で、つまんだタスクならその日時（`taskTimesOf`）から始まる。枠が動いていなければ日時はそのまま（つまんだだけ・終日を切り替えただけで、開始の無いタスクに開始が付いたり、日時が枠の形に丸められたりしない）。

- 落とした所を**開始**にする。時間軸ならその日時、日の並びなら日だけが決まるので、終日のタスクはその日、時刻を持つタスクは元の時刻（開始、無ければ期限）のままその日へ移す。日時の無いタスクは落とした日を開始日にした日だけのタスクになる。WHY 開始: タスクは開始が未来ならその日に置かれるので、未来の日へ動かしたタスクはその日に現れる。期限だけを動かすと、置かれる日（開始の日か今日）は変わらず、動かしたのに元の日に残って見える。
- 期限は元の開始〜期限の長さを保ってずらす（開始が無ければ、枠を動かした分だけずらす）。長さを保つので、開始と期限の前後は元のまま。
- 時間軸のタスクは開始の時刻に置かれるので、未来へ動かしたタスクは落とした所に現れる。過去・今日の開始に落としたタスクは、表示規則（[events.md](events.md)）で今日の位置に置かれる（今日の開始なら落とした時刻）。

入力は予定と同じクイック入力（`QuickItemForm`。状態も予定と同じ `use-quick-form.ts`）。予定とタスクで違う日時の扱いは、下書きの種類ごとの扱い（`DraftOps`。予定は `event-draft.ts` の `eventDraftOps`、タスクは `task-draft.ts` の `taskDraftOps`）に閉じ、フックは種類で分岐しない。スマホでは画面の下半分のシートの下の段（タイトル・開始と期限の見出し・参加者）から始まり、上の段まで広げるとタスクの全項目（`WhenFields` と `ExtraFields`。全項目のフォームの `ItemFields` と同じ部品）になる。PC は吹き出しで、「その他のオプション」はタスクの全項目のフォーム（`ItemForm`）へ移す。保存・直す対象・繰り返しの回の扱いは予定と同じ（上記）。

- 日時は枠とタスクの日時（下書きの `task`）から導き、入力の側には持たない。上の段で直した日時は、下の段に戻るときに枠とタスクの日時の両方へ戻す（`taskDraftFromInput`。開始の所に枠を置き、タスクの日時を入力した値にするので、期限は入力したまま残る）。開始が空なら枠に置けないので、枠はそのままにする。
- タスクの日時を直している物（下書きの `item`）とは別に持つのは、`item` が保存の宛先で、追加するタスクや予定から切り替えたタスクには無いから。`item` に持たせると、追加するタスクの期限を入れる場所が無くなる。
- 終日かどうかも予定と同じく下書きが持つ（タスクの日時の `allDay`）。切り替えると日時はそのまま（終日なら日付として読み、時刻ありに戻せば元の時刻）で、枠だけを開始の所の形（1 日の帯・時間軸のブロック）に置き直す（`withTaskAllDay`）。入力の側に状態を持たないので、見出し・枠・保存する日時が食い違わない。

## 予定とタスクの切り替え

切り替えの規則（引き継ぐ項目と日時）は [events.md](events.md#予定とタスクの切り替え)。ここにはクイック入力とグリッドでの扱いだけを書く。

- クイック入力の上端の帯（閉じると保存の間）に切り替えを置く。PC の吹き出しは閉じるの左に置く。帯はシートをどこまで下げても見えているので、下の段のまま切り替えられ、シートの高さは増えない。
- 下書きの日時の置き換え:
  - 予定 → タスク: 開始の所に期限なしのタスク（`task-draft.ts` の `newTaskTimes`）。時間指定なら開始の時刻、終日なら最初の日。
  - タスク → 予定: 開始から 1 時間（タップで作る予定と同じ。日の終わりで止める）、終日ならその日 1 日（`draft.ts` の `toEventRange`）。
  - 上の段で直した日時は、切り替える前に下書きへ映す（`useQuickForm` の `switchKind`）。引き継ぐのは入力欄で直した開始になる。
- **グリッドの枠も連動する**: タスクの枠は置いたタスクと同じ形（時間軸なら開始から最小の長さのブロック、日の並びなら 1 日の帯。`toTaskFrame`）で、端の丸・線を出さず（`hasEnds` は枠の種類で決まる）、置いたタスクと同じチェック印を添える（`DraftBlock` / `DraftBar` の `kind`）。タスクに切り替えた下書きは、空いている所をなぞり直してもタスクのまま（なぞった範囲の開始に置く）。
- 枠の種類は下書きのタスクの日時（`GridDraft` の `task`）があるかで決まり（`draftKind`。種類を別に持つと、種類と日時が食い違いうる）、直している物（`item`）の種類とは別。保存の宛先は今までどおり `item` で決まる。
- 予定とタスクで 1 つのコンポーネント・1 つのフック（`useQuickForm`）にしているのは、種類ごとに分けると切り替えたときに入れ物ごと作り直して入力が消えるため。作り直すのは日時の入力欄と期限前の通知だけ（`carriedValues`）。

## 祝日

祝日（[holidays.md](holidays.md)）は、日付の数字（`DayNumber`。月・週・日の表示と年月の選択で共通）を日曜と同じ赤で出す。祝日の一覧は項目と同じ `calendar.get` の結果（月のキャッシュ）から `useCalendarDays` で受け取る（上記「API」）。

## 天気

日付の枠（月表示のセル、週・日表示の見出し）の右端に、その日の東京地方の天気をアイコンで出し、その右に東京の最高気温を出す（`DayWeather`）。天気の取得・保存とアイコンの組み立ては [weather.md](weather.md) に書く。天気の名前（「晴時々曇」など。[weather.md](weather.md#天気の名前)）はホバーと読み上げで出す。

- アイコンと気温は週間天気の画面（[weather.md](weather.md)）へのリンクで、押せるのはアイコンと気温の所だけ（枠の残りは月表示なら日表示へ移るなど、枠の操作のまま）。
- 週表示の見出しは枠ごと押すと日表示へ移るボタンなので、リンクをボタンの中に入れ子にせず、ボタンを枠いっぱいに敷いてその上に中身を重ね、中身は天気のリンクだけを押せるようにする（`TimelineHeader`。入れ子にすると押したときにどちらが動くかがブラウザ任せになり、読み上げでも 1 つのボタンとして読まれる）。
- 枠が狭いときは、横並びのアイコン（`/` `→`）、気温、アイコンの順に諦める（日付の数字に重ねない）。変わり方の印を気温より先に諦めるのは、どの天気が混ざるかは重ねた形でも分かり、変わり方は名前でも分かる一方、気温はほかで分からないため。月・週表示は枠を「左の余り・数字・右の余り」の 3 列に分け（`CenteredWithWeather`）、数字を中央に保ったまま天気を右の余りに出す。横並びは、右の余りに横並びと気温が一緒に入らなければ CSS のコンテナクエリで 1 文字分に重ねた形（[weather.md](weather.md#アイコン)）に切り替える（気温の幅は字数分の `ch` と見る。`ch` は数字 1 字の幅で、「°」「-」はそれより狭いので上限になる）。気温は右の余りの 1 行に入りきらなければ折り返して切れ、アイコンは右の余りが正方形のアイコンより狭いときにコンテナクエリで隠す。入るかどうかはブラウザが実際の幅で決めるので、JS で幅は測らない。目安として、PC の月表示は横並びと気温、タブレットの週表示は重ねた形と気温、スマホの月表示は重ねた形だけ、スマホの週表示は出さない。日表示の見出しは数字を左に寄せて置くので、常に横並びと気温が出る。
- アイコンは週間天気の同じ日のアイコンと同じ名前を持ち、行き来するとその場から動く（[weather.md](weather.md)）。
- 最高気温は予報に無い日は出さない。最低気温と降水確率はカレンダーには出さず、ホームのタイルと週間天気の画面で出す（[weather.md](weather.md)）。
- クライアントは項目と同じ `calendar.get` の結果（月のキャッシュ）の `weather` から、日ごとの天気と 3 時間ごとの天気を受け取る（DB も 1 往復で読む。`repository.findBetween`）。見出しと月のセルは表示に掛かる月を（`useCalendarDays`）、日表示の時刻の欄はその日の月を（`useHourlyWeather`）引く。取り直すのも項目と同じく、画面に入ったときと予定・タスクを書き込んだ後。WHY NOT 日ごとと 3 時間ごとを別に読む: 日表示は両方を出すので 1 画面で 2 回問い合わせることになる。3 時間ごとの天気は同じ天気をまとめると 1 日に数個で、月表示で使わない分も小さい。まだ届いていない月や表に無い日（取り始める前の日・予報の無い先の日）にはアイコンを出さない。

### 3 時間ごとの天気

日表示では、時刻の欄の左端に東京地方の 3 時間ごとの天気を出す（`HourlyWeatherColumn`）。天気が変わる時刻にアイコンを置き、その下に次の変わり目まで縦線を引く。天気の名前（「くもり」など）はホバーと読み上げで出す。

- 予定の脇に添える補助の情報なので、時刻の字と同じくらいの小さなアイコン（12px）を、時刻の字より控えめなグレー（`text.disabled`）で出し、線はさらに薄くする。欄は日表示のときだけ、その分（14px）広げる。天気が届く前から広げておくのは、届いたときに時間軸が横にずれないようにするため。
- 週表示には出さない。時刻の欄は 1 本で、列ごとに違う日の天気を出し分けられない。
- アイコンは変わり目の時刻の字と縦の中央を揃える（気象庁の区切りは 0 時から 3 時間ごとで、時刻の目盛りと重なる）。0:00 から始まる区間だけは、上にはみ出さないよう上端に揃える。縦の位置は予定のブロックと同じく `atMinute` の calc で決めるので、つまんで伸び縮みしても付いてくる。
- 読み出し（日ごとの天気と同じく `calendar.get` の `weather.hourly`）では、同じ日に間を空けずに続く同じ天気を 1 つの区間にまとめ、日付とその日の 0:00 からの分（開始・終了）で返す。区間は日をまたがないので、同じ天気が日をまたいで続いても日ごとに分かれ、どの日も最初の区間の頭にアイコンが出る。

## API

`calendar.get`（`server/features/calendar/`）が入力の `from`〜`to`（JST 日付、両端含む）の 1 期間分（`shared/calendar.ts` の `CalendarPeriod`）を返す: `items` は `CalendarItem[]` を `placementDate` 昇順、`holidays` はその期間の祝日（下記「祝日」）、`weather` はその期間の天気（下記「天気」）。面（月のグリッド・週／日の見出し）は 3 つを必ず一緒に出すので 1 回の問い合わせにまとめ、祝日と天気も表示する期間の分だけを送る。画面は月ごとに 1 回ずつ呼ぶ（キャッシュの単位が月）が、画面に入ったときに取り直す何か月分は同じ時点に出るので、1 本の要求にまとまって届く（[architecture.md](../architecture.md#通信の往復)）。

WHY NOT 祝日と天気を別の問い合わせで丸ごと配る: 面を出すたびに問い合わせが 3 本になり、使うのは表示している期間だけなのに、取っておいた全期間（祝日は 1955 年からの千数百日、天気は取り始めてからの毎日で増え続ける）を送ることになる。祝日と天気は手元の表を読むだけで、配布元へは取りに行かない（配布元が遅い・落ちているときに項目の応答まで待たせない）。

項目は、`server/features/events/occurrences.ts` が繰り返しを展開し、`shared/calendar.ts` の規則で予定に `placementDate`（複数日は日ごと）を付与し、タスクに表示規則を適用する。クライアントは楽観的更新（`src/features/events/optimistic.ts`）で同じ `shared/calendar.ts` を使い、規則を別実装しない。

同日内の順序は「終日の予定 → 終日のタスク（未完了）→ 時刻のある項目 → 時刻の無いタスク」。項目の時刻は、予定は開始、タスクは `shared/calendar.ts` の `taskTime`（完了 → 開始 → 期限の優先）で、一覧の行やタイムラインのブロックが示す時刻と同じものを使う。

### CalendarItem

```ts
type Occurrence = {
  id: string;                    // 繰り返し元（単発ならその行）の id
  kind: 'event' | 'task';
  occurrenceStart: string | null; // 繰り返しの回を指す基準日時。単発は null
  title: string; allDay: boolean; startsAt: string | null; endsAt: string | null;
  completedAt: string | null; location: string | null; note: string | null;
  participantIds: string[]; rrule: string | null;
  remindStartMinutes: number | null; remindEndMinutes: number | null;
  isRecurring: boolean; isModified: boolean;
};
type CalendarItem =
  | (Occurrence & { kind: 'event'; startsAt: string; endsAt: string; placementDate: string; dayIndex: number; dayCount: number })
  | (Occurrence & { kind: 'task'; placementDate: string; isOverdue: boolean });
```

`placementDate` は JST の `YYYY-MM-DD`。予定は開始日（複数日にまたがる予定は日ごとに 1 件）、タスクは [events.md](events.md) の表示規則で決める。

### キャッシュ

- 取得のキャッシュは JST の暦月単位（`calendarMonthQueryOptions`。キーは `['calendar', 'YYYY-MM']`）で、表示に必要な範囲は `useCalendarItems(range)` が範囲に掛かる月を繋いで返す。祝日と天気は同じ月のキャッシュから `useCalendarDays(range)`（`src/features/calendar/queries.ts`）が読むので、項目を出している面なら問い合わせは増えない。表示範囲をキーにすると月・週・日・リストの切り替えごとに別のキーになり、必ず一度空になってしまう。暦月なら同じ日を見ているどの表示も同じキャッシュに当たるので、切り替えても手元の内容がそのまま出る。
- 月のキャッシュは古くならない（`staleTime` は無期限）。サーバーに問い合わせるのは「まだその月を持っていないとき」「画面に入ったとき」「予定・タスクを書き込んだ後」（`useOptimisticMutation` の invalidate）だけで、表示（月・週・日・リスト）の切り替えでは取り直さない。既定の `staleTime: 0` だと、切り替えのたびに月を読む側（面・リスト）が付け替わるのでそこで毎回取り直しになる。
- 画面に入ったときの取り直しは `useRefreshCalendarItems`（`queries.ts`）がマウントの 1 回だけ行う。カレンダー画面（`use-calendar-page.ts`）が呼ぶので、別の画面との行き来と再読み込みでは取り直し、同じ画面に留まる間（表示の切り替え）は取り直さない。出している月はその場で取り直し、キャッシュにあるだけの月には古い印を付けて、その月を次に出すとき（スワイプで移った先など）に取り直す。
- 月は互いに重ならず、サーバーが月をまたぐ予定を日ごとの項目にして返すため、繋ぐときは範囲で絞るだけでよい（重複せず `placementDate` 順も保たれる）。タスクの表示規則も「未完了の先頭 2 件」を発生の先頭から数えるので、月に分けても結果は変わらない。
