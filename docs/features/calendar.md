# カレンダー（calendar）

## 目的

予定とタスク（[events.md](events.md)）を 1 つの時系列に見せる画面の feature。サーバー側の feature は持たず、データの読み書きはすべて `events` の API に送る。

## 画面

| 画面 | パス | 内容 |
|---|---|---|
| カレンダー | `/calendar?view=month\|week\|day\|list&date=YYYY-MM-DD`（リスト表示の絞り込みは `from` / `to` / `kind`=`all\|event\|task` / `participant`=`all` かユーザー ID / `completed`=`all\|open\|done` / `q`） | 予定とタスクを 1 つの画面で、月（グリッド）・週／日（タイムライン）・リストの 4 通りに表示し、追加・編集・削除する。初期表示は今月の月表示。 |

表示は AppBar 右端のメニューで切り替える。すべて `CalendarItem[]` だけを読み、予定とタスクの差は描画と操作（完了の有無）にのみ現れる。部品は MUI で自作（`src/features/calendar/components/`）し、汎用カレンダーライブラリは使わない。週の始まりは月曜。

- **月**（`MonthGrid`）: Google カレンダー流のレーン配置。週ごとに、複数日・終日の予定を「開始列と長さ」の順に 1 本のバー（開始日・終了日だけ角丸）として先に置き、残りの日ごとの項目（時刻付き予定は「● タイトル」、タスクはチェック印付き）を空いたレーンに詰める（`lane-layout.ts`）。行の高さに入りきらないレーンは「+n」。完了したタスクは日ごとに一番後ろへ回し（`completedLast`）、「+n」に先に入るようにする。グリッドは画面の残り全部を占め、レーン数は行の高さから実測する。日表示へは、スマホならセルのタップ、PC なら日付の数字から移る（スマホでは項目はタップできず、セルのどこを押しても日を選ぶ。PC では項目をクリックすると詳細）。セルをなぞると終日の予定を追加できる（PC は空いている所のクリック、スマホは長押しから。タップは日表示に譲る）。出ている枠に掛かるセルを押したときは、選び直さずにその枠をつまむ。枠は終日でも時間指定でも帯で出す（時間指定はその日 1 日ぶん）。保存済みの予定も長押しでつまむと編集モードに入り、同じ指のまま別の日へ動かせる（下記「予定を長押しして直す」）。
- **週・日**（`TimelineView` + `TimeGrid`）: Google カレンダーと同じタイムライン。上に日付の見出しと終日欄（終日・複数日の予定、時刻の無いタスク。月と同じレーン配置）、下に 0〜24 時の時間軸（`TimeGrid`。縦にスクロールする部分）。時間指定の予定は開始〜終了の高さの塗りブロック、時刻付き（`taskTime`。完了 → 期限 → 開始の優先）のタスクはその時刻に薄い背景の小さなブロック。同じ時間帯に重なる項目は横に並べる（`timeline-layout.ts`: 重なり合う集まりごとに列を割り当て、幅を等分）。今日の列には現在時刻の赤い線。縦の位置を合わせるのは最初に出したときだけ（今日なら現在時刻の少し上、それ以外は 7 時）で、日付を移っても見ていた時間帯を保つ。2 本の指でつまむと 1 時間あたりの高さが変わり、時間軸が縦に伸び縮みする（`use-pinch.ts` / `use-hour-zoom.ts`。下記）。週表示で日付の見出しをタップすると日表示へ。空いている所をなぞると時間帯（15 分刻み、最短 30 分）、終日欄をなぞると日（終日の予定）を選んで追加できる。時間軸の枠はスマホならつまんで直せる（端の丸で開始・終了、枠そのもので長さを保ったまま移動。週表示では左右に動かして別の日へ持っていける）。保存済みの予定も長押しでつまむと同じ枠になる（下記「予定を長押しして直す」）。終日欄の帯は月表示と同じ見た目で、丸は出さずにセルからつまむ。終日の予定も長押しでつまむと編集モードに入る。
- **リスト**（`ListView`）: 時系列の一覧（Google カレンダーの「スケジュール」）。AppBar に検索、絞り込みボタンで期間・種別（予定／タスク）・参加者・完了状態を開く。既定の期間は「表示中の日の前 7 日〜後 21 日」。
- **状態**: 表示・日付・絞り込みは検索パラメータ（`use-calendar-page.ts` がそこから期間・見出し・前後の移動を導き、ページは描画だけ）。表示や日付の切り替え（表示の選択、日のタップ、選択ダイアログ、今日）は履歴に積み、戻るで前の表示に戻れる。スワイプでの前後移動と絞り込みの入力は履歴を置き換える。どちらも入力中の下書き（下記）は閉じない（[architecture.md](../architecture.md) のダイアログと履歴）。URL に載せない状態（打ちかけのキーワード、時間軸の高さ）も `use-calendar-page.ts` が持つ。画面の状態を探す所を 1 か所に保つため。キーワードは URL を置き換えるだけにする（`src/lib/search.ts`）。
- **移動**: AppBar の見出し（月なら年月、週なら期間、日なら日付）をタップすると選択ダイアログ（`DatePickerDialog`）。見出しが指す単位と選べる単位を揃え、月表示は年を ‹ › で送って 12 か月から、週・日表示は月を ‹ › で送って月グリッド（月表示と同じ 6 週）の週の行・日から選ぶ。選んだ範囲が今日を含むときは今日へ移る（「今日」が選ばれている見え方に揃える）。月・週・日の表示は左右にスワイプすると前後の月・週・日へ。前後ボタンは置かない。「今日」ボタンで今日へ。
- **スワイプ**（`SwipePager`）: 前・今・次の 3 面（`CalendarPane`）を横に並べた横スクロール + スクロールスナップ。指への追従・慣性・吸着はブラウザに任せ、吸着し終えた面（`scrollend`）が中央でなければ日付を移して中央に戻す。面ごとに自分の範囲を読むので、スワイプした先の予定も先に読み終えている。日付の移動は router の遷移なので、その描画が終わるまで面を中央に戻せず、戻るまでは端に張り付いて続けてスワイプしても動かない。そこで 1 回の移動で描き直す量を減らしてある: **面の key は受け持つページ**（代表する日）にして、1 つ進んでも変わらない 2 面は React がそのまま使い回す（key を位置にすると 3 面とも中身が入れ替わって全部描き直しになる）。**面（`CalendarPane`）は `memo`** で、props（表示と代表する日）が同じなら描き直さない。期間は代表する日から面の中で組み立て（`periodOf`）、渡す関数はページ側で固定する（毎回別の値・別の関数だと使い回しても描き直しになる）。**中身を描くのは表示中の面と既に描いてある面だけ**で、新しく要る端の 1 面は次の描画（transition）で足す（枠となる 3 つの箱は中身の有無に関わらず並べたままにして、横スクロールの寸法と中央に戻す計算を変えない）。これで移動そのものの描画は空になり、中央へすぐ戻れる。足す描画も transition なので、描き終わる前に次のスワイプが来たら捨てて描き直す。表示中の面だけは必ずその描画で描き切る（View Transition が切り替え直後の描画を撮るため。下記）。日付の移動では router のスクロール位置の復元を止める（`resetScroll: false`。復元されると中央に戻した面が元の位置へ引き戻され、スワイプ 1 回でページが延々と送られる）。中央以外の面は `inert` + `aria-hidden`（フォーカスが入ると勝手にページが移るのと、同じ項目が読み上げや自動操作に重複して見えるのを防ぐ）。縦にスクロールする時間軸は横に動かすたびに 3 面で位置を揃える。縦スクロール・横スワイプの切り分けもブラウザのスクロールに任せる。
- **拡大縮小**（`use-pinch.ts` + `use-hour-zoom.ts`）: 週・日の時間軸を 2 本の指でつまむと、1 時間あたりの高さが指の間隔と同じ倍率で変わる（24〜240px）。渡すのは始めた時点からではなく直前からの倍率なので、受け取る側は上限・下限で止めるだけでよい（始点からの比だと、止まったあとも比が伸び続けて戻すときに効かない時間ができる）。高さは小数のまま持ち、渡すのは整数に丸めた値にする（指をゆっくり動かしたときの僅かな倍率も積もって効き、渡す先から見れば高さは整数しか取らないので、同じ高さの間は面を描き直さずに済む）。**1 時間の高さはグリッドに CSS 変数（`--hour-height`）で置くだけで、時間軸の中の寸法（時刻の目盛り・1 時間ごとの罫線・予定のブロック・下書きの枠）はすべてそこからの `calc` で決まる**（`use-hour-zoom.ts` の `atMinute`）。伸び縮みで変わる値は 1 つなので、指に合わせて何十もの寸法を JS で組み直さず、その数だけ使い捨ての CSS が作られることもない（つまむ前後で増える CSS 規則は 100 フレーム動かしても数個）。**px を組み立てるのは CSS だけ**で、JS が高さの数を持つのは CSS 変数へ渡す所と、伸び縮みを察してスクロール位置を合わせ直す所だけ。なぞったときの分は列の高さ（＝1 日）に対する割合から（`use-time-drag.ts`）、最初の縦位置と枠を見える所へ送る判断は時間軸の `scrollHeight` から引く。ブロックに時刻の行を添えるかどうかも `@container (min-height: …)` で決めるので、同じ寸法の規則が JS と CSS に二重に書かれる所は無い。高さの状態はカレンダー画面に 1 つだけ置き、スワイプの 3 面すべてに同じ値を渡す（面ごとに持つと、拡げたあとスワイプした先だけ元の高さに戻る）。伸び縮みしたら画面の真ん中に見えていた時刻をそのままの位置に残す（上端を固定すると、拡げるたびに見ていた時間帯が下へ流れていく）。3 面が同じだけ動くので縦位置は揃ったままになる。つまみ始めたら 2 本とも自分でポインタを受け取り（`setPointerCapture`）、タッチの既定の動きを止める（2 本指はブラウザにとってスクロールなので、止めないと拡げ縮めと同時に画面が流れる。止め方は範囲選びと同じ `touch-block.ts` の 1 か所に置く）。1 本だけのスクロール・なぞりはそのまま通す。別の指が触れたら範囲選び（下記）はやめてこちらに譲る。ブラウザ自身の拡大縮小は全画面で止めてあり（`touch-action: pan-x pan-y`。[../architecture.md](../architecture.md)）、つまむ操作が効くのはこの時間軸だけ。
- **表示の切り替え**: 月・週・日・リストを切り替えると View Transition で繋ぎ、両方の表示に在る項目はその場から新しい位置へ動く（それ以外はフェード）。項目の名前は `components/item-transition.ts` が発生（繰り返しの 1 回）ごとに決める。名前は文書の中で一意でなければならず重複すると遷移そのものが行われないので、同じ発生が複数描かれる所は 1 つに絞る: 複数日の予定は初日だけ（月グリッドは週の行ごとに帯が分かれ、リストは日ごとに行が並ぶ。続きの日はフェード）、スワイプの控えの面（`inert`）は対象にしない（`src/lib/theme.ts`）。遷移の前後として比べられるのは切り替え直後の描画なので、**表示中の面の項目はその描画に載っていなければならない**（あとから足される物は動かずに出るだけになる）。前後の面は `inert` で対象外なので、要るのは表示中の面だけ。日付だけが変わる移動（スワイプ・今日・選択ダイアログ）では遷移しない。
- **色**: 参加者が 1 人の項目はそのユーザーの色（[users.md](users.md)）。共有の項目（参加者が 1 人でない）は無彩色。まだ保存していない下書きの枠も同じ規則で、選んでいる参加者の色になる。
- API 上は複数日の予定が日ごとに 1 件（`dayIndex` / `dayCount`）で返るので、グリッドとタイムラインの終日欄はそれをバーに束ねる。リスト（`DayList`）では日ごとの行のまま表示する。

## グリッドから予定を追加する（下書き）

Google カレンダーと同じく「範囲を選ぶ → その場で入力 → 保存」で追加する。選んだ範囲（まだ保存していない予定）を **下書き**（`draft.ts` の `EventDraft`。時間指定か終日かの 2 通り）と呼び、状態はページ（`calendar.tsx`）が 1 か所で持つ。選んでいる参加者も下書きの一部としてページが持つ: 枠の色（`colorUserOf`）とクイック入力のチェックボックスが同じ値を見るので、参加者を変えると枠の色もその場で変わる。既定は自分だけで、枠を動かしても選んだ参加者は持ち越す。

1. **選ぶ**: グリッドをなぞる（`use-range-drag.ts`）。マウス・ペンは押した時点から、タッチは長押しから始め、タップや縦スクロール・横スワイプと分ける。1 つのドラッグは 1 本の指だけのもので、別の指が触れたらそのドラッグは終わる（時間軸ではそれがピンチの始まり）。別の指がどこに降りるかは選べないので、掴んだ要素ではなく文書全体で見る。時間軸はタップでも選べて 1 時間になる（月表示のタップは日表示に譲る）。時間軸は 15 分刻みに吸着し（`use-time-drag.ts`）、月表示と終日欄は日単位（`use-day-drag.ts`）。範囲が変わるたびに震えて区切りを指に返す（`useRangeDrag` の `vibration`。長さを決める規則は `draft.ts` の `timeVibration` / `dayVibration` に置き、汎用のドラッグは時刻や日の意味を知らない）。範囲は state に持たずページに渡し、描画は下書きの枠（`DraftBlock`）に任せる。ドラッグは「何をつまんだか」（`draft.ts` の `TimeGrab` / `DayGrab`。空いている所なら null）と押した所・今の所の組（`Drag`）で表し、そこから範囲を出す計算は `timeDraft` / `dayDraft` に閉じる（`use-range-drag.ts` は掴んだ物の意味を知らない）。
2. **調整する**: 出ている枠はつまんで直せる（時間軸はスマホだけ。PC は吹き出しが前に出て触れない）。選び直しでもつまんで動かしたときでも、範囲が変わるたびに震える。表示を切り替えても下書きは残り、切り替えと同時に下書きの初日（複数日なら最初の日）へ移るので、月で日を決めてから週・日で時間を詰める、といった直し方ができる。移らずに見ていた日のままだと、下書きが画面の外に出て見失う（月表示で選べる日は、週・日の表示が一度に出せる日より多い）。日付そのものを動かす移動（「今日」・スワイプ・日のタップ・選択ダイアログ）は行き先を名指しした操作なので、下書きは連れていかない（下書きが画面から出るのは求めた通りの結果）。表示の切り替えだけが、同じ日を見ているつもりのまま出せる期間の広さを変えるので連れていく。
   - **時間軸（週・日）**: 枠の端の丸（8px。指の当たりだけ 32px に広げる）をつまむと開始・終了だけが動き、反対の端は越えられない（15 分だけ残す）。丸以外の枠をつまむと長さを保ったまま動く。どちらも押した時点から動き出す（長押しは待たない。枠は「今つまんでいる予定」なので、そこに触れるのは直すときだけ。縦スクロールと横スワイプは枠の外から始める）。どちらも一番近い 15 分に吸着する。震えの長さは吸着した時刻で決まり、正時は 50ms と長く、15・30・45 分は 10ms と短くして、時間の区切りを見ずに分けられるようにする。基準は動いた側の時刻で、枠ごと動かして両方が動くときは開始時刻。日が変わるのは枠そのものを動かしたときだけで、週表示で左右に動かすと指の下の列の日へ移る（端の丸と、空いている所からの選び直しは始点の日のまま）。枠は列の中ではなく列に重ねて置き（そのため時間軸のグリッドは子の置き場所をすべて明示する）、日が変わっても同じ要素のまま列を移る。列の中に置くと日ごとに要素が入れ替わり、掴んでいた要素が DOM から消えた時点でタッチが途切れて横スワイプに化けてしまう。枠はポインタを受けるので、枠の中から選び直すことはできない（空いている所から選び直す）。
   - **日の並びの帯（月表示、週・日の終日欄）**: 帯は丸も出さず、ポインタも受けない見せるだけのもの（`DraftBar`）で、つまむのは下の日のセル。押したセルが最初の日の左半分なら開始、最後の日の右半分なら終了、それ以外の掛かっている所なら帯ごと（日数を保ったまま）動かす（`dayGrab`）。ここも時間軸と同じく押した時点から動き出す（長押しを待つのは空いている所からの選択だけ。帯に掛かる所を押すのは直すときだけなので、日表示へのタップや横スワイプは帯の外から始める）。帯そのものを押す作りにしないのは、帯が指より薄い（月グリッドで 17px）ため狙って押せず、月グリッドでは週の行ごとに帯が分かれていて、行をまたいで動かすと掴んだ要素が DOM から消えてしまうため。端は反対の端を越えられない（1 日だけ残す）。月グリッドで下の行へ動かせば 1 週間ぶんずれる。震えは日をまたぐたびに 10ms で、区切りが 1 種類しか無いので長さも 1 つ（長い 50ms は時間軸の正時だけの合図に取っておく）。
     月グリッドには時間指定の下書きもその日 1 日ぶんの帯で出す。日の並びでは時間帯を変えられないので、つまめるのは帯そのものだけで、時間帯を保ったまま日が動く（時間帯は週・日の時間軸で直す）。週・日の終日欄には終日の下書きしか出さない（時間指定はそちらの時間軸に枠で出るため）。
   - Vibration API の無いブラウザ（iOS）では震えは何も起こらない。PC は吹き出し（モーダル）が前に出てグリッドに触れないので、選び直すかその他のオプションで直す。
3. **入力して保存する**: クイック入力（`QuickEventForm`）。保存すると一覧を取り直し、予定がその場に出て下書きは消える。開く段は入口で決まる: グリッドからは下の段、追加ボタンからは上の段（全項目）。
   - **スマホ**: 画面下のシート（`src/lib/ui/BottomSheet.tsx`）。ダイアログには移らず、同じシートの見える量だけが変わる。下の段はタイトル・日時の見出し・参加者だけ、上の段（画面いっぱい）は全項目（終日・開始・終了・場所・メモ・繰り返し・通知）。項目はどちらの段でも DOM にあるので、どこまで広げていても同じ 1 つの `<form>` として保存できる。上の段で日時を直して下の段に戻ると、その日時を下書きに映してグリッドの枠と見出しに反映する（日をまたぐ時間指定など枠に出せない範囲だけは枠をそのままにする）。
   - **PC**: 下書きに寄せた吹き出し。タイトルと参加者だけを扱い、足りない項目は「その他のオプション」で入力済みの内容ごと全項目のフォーム（`EventForm`）へ渡す。直している予定も一緒に渡すので、そちらで保存しても同じ予定の上書きになる（見出しと繰り返しの扱いもそれに合わせる）。吹き出しの外をクリックすると下書きを捨てる。
   - 全項目の並び（日時・場所・メモ・繰り返し・通知）は `EventFields.tsx` に切り出し、全項目のフォームとシートで同じものを使う。値の組み立ても `eventInputFromForm`（`form-values.ts`）で共通にし、フォームが増えても項目とキーがずれないようにする。

## 予定を長押しして直す（編集モード）

保存済みの予定は、**長押しでつまむと編集モード**に入る。つまんだ予定はその場で下書きと同じ枠（時間軸なら `DraftBlock`、日の並びなら `DraftBar`）になり、**指を離さずにそのままなぞれば**長さ（時間軸なら時間、日の並びなら日数）を保ったまま動かせる。離した後も編集モードのままで、枠は長押しを待たずに動く。入力は追加と同じクイック入力（`QuickEventForm`）で、既定値がその予定の内容（タイトル・場所・メモ・繰り返し・通知）になるだけ。保存すると同じ予定を上書きし、シートを閉じれば何も変えずに終わる。

月・週・日のどの表示でも操作は同じで、直せる範囲だけがその表示で見えているものに従う（時間軸では時間帯と日、日の並びでは日）。表示を切り替えても編集は続くので、月で日を決めてから週で時間を詰める、という直し方ができる。

- 枠と「直している予定」は 1 組（`draft.ts` の `Draft`）で扱い、ページ（`calendar.tsx`）が 1 か所で持つ。ドラッグは範囲と対象を一緒に返すので、つまむたびに何を直しているかが決まる（空いている所をなぞれば対象は無くなり、新しい予定の下書きになる）。
- 保存の宛先は対象だけで決まる: 対象があれば上書き（`useUpdateEvent`）、無ければ追加（`useCreateEvent`）。入口（クイック入力／その他のオプション）では変わらない。繰り返しの回は「この回だけ」を直す（つまんだのはその回で、ほかの回の日時まで動かさないため）。範囲の決め方は `grabbedScope` 1 か所に置き、保存の指定と入力欄の出し分け（繰り返しの設定は触らせない）が食い違わないようにする。
- 編集中の予定は枠で出すので、元のブロック・項目は**隠すが DOM からは消さない**。長押しでつまんだ要素が消えると、その場でタッチが途切れて指を離さずに動かせなくなる（横スワイプに化ける）ため。隠すのは `visibility` で、場所（レーン・列）はそのまま残す。同じ発生かどうかは暦日ではなく種別・id・繰り返しの回で見る（`sameOccurrence`。複数日の予定は日ごとに 1 件で、月グリッドでは週の行ごとに帯が分かれるため）。
- 軽いタップは今までどおりの意味（時間軸と終日欄では詳細（`ItemDetailSheet`）、スマホの月表示では日表示）。ドラッグ（`use-range-drag.ts` の `tap`）は、動かさずに離したときは何も選ばず、クリックかもしれないうちは知らせない。
- つまめるのは枠に出せる予定だけ（`itemDraft`）。タスクは長さを持たず、日をまたぐ時間指定の予定は枠で表せないのでつままない。時間軸は指で触れるスマホだけ（PC は吹き出しが前に出てグリッドに触れない）、日の並びは PC でも同じようにつまめる。

シート（`BottomSheet`）は `peekRef` を渡して上・下の 2 段で止める使い方で、下の段からさらに下げると閉じる。指に追従して動き、離すと動かした向きへ 1 段ぶん進む（40px 以上動かしたときだけ。それ以下なら元の段に戻る）。この使い方では高さは常に画面いっぱいで `translateY` の量だけを変え、止まる位置は「下の段でも見える部分」の実測から決める。モーダルにしないので、下の段では後ろのグリッドをそのまま触れる（枠の端をつまんで時間を直せる）。なぞり始めるのはつまむ帯に限らず、入力欄の上からでもよい。同じシートを段を持たない使い方（記録 1 件の追加・詳細・編集 = `RecordSheet`）でも使う（[architecture.md](../architecture.md)）。上端の帯（閉じる・保存）もクイック入力と `RecordSheet` で同じ `SheetHeader` を使う。

スマホのシートがキーボードに隠れないよう、`index.html` の viewport に `interactive-widget=resizes-content` を指定している（キーボードが出たら表示領域自体を縮める）。

## CalendarItem

```ts
type Occurrence = {
  id: string;                    // 繰り返し元（単発ならその行）の id
  kind: 'event' | 'task';
  occurrenceStart: string | null; // 繰り返しの回を指す基準日時。単発は null
  title: string; allDay: boolean; startsAt: string | null; endsAt: string | null;
  completedAt: string | null; location: string | null; note: string | null;
  participantIds: string[]; rrule: string | null;
  remindStartMinutes: number | null; remindEndMinutes: number | null;
  isRecurring: boolean; isModified: boolean;
};
type CalendarItem =
  | (Occurrence & { kind: 'event'; startsAt: string; endsAt: string; placementDate: string; dayIndex: number; dayCount: number })
  | (Occurrence & { kind: 'task'; placementDate: string; isOverdue: boolean });
```

`placementDate` は JST の `YYYY-MM-DD`。予定は開始日（複数日にまたがる予定は日ごとに 1 件）、タスクは [events.md](events.md) の表示規則で決める。

## API

`GET /api/events?from&to`（[events.md](events.md)）が `from`〜`to`（JST 日付、両端含む）の `CalendarItem[]` を `placementDate` 昇順で返す。`server/features/events/occurrences.ts` が繰り返しを展開し、`shared/calendar.ts` の規則で予定に `placementDate`（複数日は日ごと）を付与し、タスクに表示規則を適用する。クライアントは楽観的更新（`src/features/events/optimistic.ts`）で同じ `shared/calendar.ts` を使い、規則を別実装しない。同日内の順序は「終日の予定 → 時刻のある項目 → 時刻の無いタスク」。項目の時刻は、予定は開始、タスクは `shared/calendar.ts` の `taskTime`（完了 → 期限 → 開始の優先）で、一覧の行やタイムラインのブロックが示す時刻と同じものを使う。

- 右下の追加ボタン（`AddMenu`。ホームと同じ部品で、出す種類を `kinds` で選ぶ）から予定・タスクのどちらも追加できる。タスクはその場でフォームが開く（日時なし）。予定は時間帯を見ながら入れたいので、その日の日表示へ送って既定の時間帯（次の正時から 1 時間。`defaultDraft`）の下書きを置き、グリッドからの追加と同じ流れに合流する（`add=event`。しるしは使ったらすぐ消す）。ホームから選んだときも同じで、カレンダーの日表示へ移る。下書きの間は追加ボタンを引っ込める（クイック入力と場所が重なるため）。
- 項目の詳細は `ItemDetailSheet`（`src/features/events/components/`）。読むだけで開き、鉛筆で同じ入れ物の中が入力欄に変わる（繰り返しなら範囲を先に選ぶ）。日時だけを直すならグリッドの長押し（上記「予定を長押しして直す」）のほうが早い。三点リーダーに削除と、タスクなら完了を置く。予定とタスクの違いは本文の日時の出し方と入力欄の中身だけ。リストとホームでは行のチェックボックスからも完了できる。
- 取得のキャッシュは JST の暦月単位（`calendarMonthQueryOptions`。キーは `['calendar', 'YYYY-MM']`）で、表示に必要な範囲は `useCalendarItems(range)` が範囲に掛かる月を繋いで返す。表示範囲をキーにすると月・週・日・リストの切り替えごとに別のキーになり、必ず一度空になってしまう。暦月なら同じ日を見ているどの表示も同じキャッシュに当たるので、切り替えても手元の内容がそのまま出る（ホームの「今日」カードも同じ月のキャッシュを読む）。
- 月のキャッシュは古くならない（`staleTime` は無期限）。サーバーに問い合わせるのは「まだその月を持っていないとき」「画面に入ったとき」「予定・タスクを書き込んだ後」（`useOptimisticMutation` の invalidate）だけで、表示（月・週・日・リスト）の切り替えでは取り直さない。既定の `staleTime: 0` だと、切り替えのたびに月を読む側（面・リスト）が付け替わるのでそこで毎回取り直しになる。
- 画面に入ったときの取り直しは `useRefreshCalendarItems`（`queries.ts`）がマウントの 1 回だけ行う。カレンダー画面（`use-calendar-page.ts`）とホームの「今日」カードが呼ぶので、別の画面との行き来と再読み込みでは取り直し、同じ画面に留まる間（表示の切り替え）は取り直さない。出している月はその場で取り直し、キャッシュにあるだけの月には古い印を付けて、その月を次に出すとき（スワイプで移った先など）に取り直す。
- 月は互いに重ならず、サーバーが月をまたぐ予定を日ごとの項目にして返すため、繋ぐときは範囲で絞るだけでよい（重複せず `placementDate` 順も保たれる）。タスクの表示規則も「未完了の先頭 2 件」を発生の先頭から数えるので、月に分けても結果は変わらない。

## ホームのカード

「今日」: 今日の予定と今日の位置にあるタスクを 1 つの一覧にする（`src/features/dashboard/cards/TodayCard.tsx`。カレンダーと同じ `useCalendarItems` で今日だけを読む）。1 項目 1 行で、印（予定は色の点、タスクはチェックボックス）・時刻・タイトルだけを出し、名前や終了時刻は出さない。今日完了したタスクはチェックの入った取り消し線の行として残す（完了した手応えが見え、間違えたその場で戻せる）。別の日を指す時刻（繰り越し・期限が別日）は空にする（1 行に日付を出す余白が無い）。明日以降は出さない。見出しから日表示へ。行にはカレンダーと同じ `itemTransitionName` を付けるので、ホームと予定画面を行き来するときは両方に在る項目がその場から動く（View Transition）。
