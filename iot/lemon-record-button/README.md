# レモンの記録ボタン（lemon-record-button）

M5Stack AtomS3R の画面（ボタン）を押すだけで、LifeHub にレモンの木の世話を記録する。

| 操作 | 記録 | 画面 |
|---|---|---|
| 1 回押す | 葉水（`["mist"]`） | 葉 |
| 2 回押す | 葉水＋水やり（`["mist", "water"]`） | しずく |
| 3 回以上押す | 何も記録しない（取り消し） | 消える |

画面のアイコンはアプリのレモンの画面と同じもの（`src/features/lemon/care-type-icons.tsx`）を、黒地に白で出す。本体を横向き（右に 90 度倒して）置くので、画面の絵は左に 90 度回して描く。`icons.h` は `pnpm icons:generate` がアプリのアイコンから生成するので、アプリのアイコンを変えたら生成し直す。

続けて押す間隔が 0.4 秒以内なら、続けて押したと数える。最後に押してから 0.4 秒たったら押し終わりとして、Wi-Fi に繋いで記録投入用エンドポイント（`POST /api/records`。[docs/features/api-keys.md](../../docs/features/api-keys.md)）に送り、すぐに眠りに戻る。画面は押した瞬間から今の押し方を示し、送り終えたら消える。

間違えて押したときは、そのまま連打すれば取り消せる。3 回目で画面が消えて送るのをやめ、連打が止まったらすぐに眠る。取り消しを長押しなどの別の押し方にしないのは、押し間違いに気づいたその場で、押している手をそのまま続ければ済むようにするため。送れなかったときはアイコンが灰色になって赤い × が 3 秒出る（記録されていないので、アプリから入れ直す）。

記録の日時はサーバーが受け取った時刻になる（本体は時計を持たない）。記録した人は不明になる（誰が押しても同じキーで送るので、キーを発行した人にはしない）。

## セットアップ

1. LifeHub の設定画面「外部連携」で API キーを発行し、表示されたキーを控える（1 度しか表示されない）。
2. `config.example.h` を `config.h` に写し、Wi-Fi（2.4GHz）と API キーを書く。`config.h` は `.gitignore` 済み。
3. 書き込む。[arduino-cli](https://arduino.github.io/arduino-cli/) なら、ボードのパッケージとライブラリの版を `sketch.yaml` で固定してあるので、このディレクトリで次を実行するだけでよい。

   ```sh
   arduino-cli config add board_manager.additional_urls https://static-cdn.m5stack.com/resource/arduino/package_m5stack_index.json
   arduino-cli compile
   arduino-cli upload -p /dev/ttyACM0   # ポートは環境に合わせる
   ```

   Arduino IDE なら、ボードマネージャで「M5Stack」（3.3.9）、ライブラリマネージャで M5Unified（0.2.23）と M5GFX（0.2.30）を入れ、ボードに「M5AtomS3R」、PSRAM に「Disabled」を選ぶ。

眠っている間は USB のシリアルも止まっているので、書き込めないときは側面のリセットボタンを緑の LED が点くまで（約 2 秒）長押しして離し、ダウンロードモードにしてから書き込む。

## 省電力の設計

### ライトスリープで待つ（ディープスリープにしない）

AtomS3R のボタンは G41 につながっている。ESP32-S3 のディープスリープから起こせるのは RTC GPIO（G0〜G21）だけで、G41 では起こせない（ハードウェアの制約）。そのため、押されるのを**ライトスリープ**で待ち、G41 の LOW を GPIO の割り込みとして起きる。

- 起きるのはボタンだけ。タイマーでは起きない（何もしない間は一度も起きない）。
- 眠っている間は CPU の電源も落とす（`ESP_PD_DOMAIN_CPU`）。RAM は保たれるので、起きたら続きから動く（起動し直さない）。
- 待機電流の目安は数百 µA（ESP32-S3 のライトスリープと基板の電源回路。実測はしていない）。ディープスリープ（公称 約 11µA）より大きい。
- WHY NOT 外付けのボタンを RTC GPIO（Grove の G1/G2 など）につないでディープスリープ: 待機電流は最小になるが、本体のボタンが使えなくなる。本体だけで完結することを取った。

### 使わない部品は止める

| 部品 | 扱い |
|---|---|
| Wi-Fi | 送り終えたら切断して無線ごと止める（`WIFI_OFF`）。接続情報はフラッシュに書かない |
| Bluetooth | 一度も起動しない |
| 液晶（GC9107） | 押してから送り終えるまで以外は SLEEP IN |
| バックライト（LP5562） | 明るさ 0 に加えて CHIP_EN を落とし、スタンバイにする（明るさ 0 だけでは内部の発振器が動き続ける） |
| IMU（BMI270 / BMM150） | 初期化しない（電源投入時の低消費の状態のまま） |
| PSRAM | 初期化しない（`PSRAM=disabled`） |
| シリアル | 開かない |

### 起きている時間を短くする

電池を食うのはほとんどが Wi-Fi の無線なので、繋いでいる時間を短くすることを優先する。

- 押されたらすぐに Wi-Fi の接続を始め、押し終わりを待つ時間（最後に押してから 0.4 秒）を接続の待ち時間に重ねる。連打で取り消したら、その時点で無線を止める。
- 2 回目の接続からは、前回のアクセスポイントのチャンネルと BSSID を指定して繋ぐ（チャンネルの走査を省く）。3 秒で繋がらなければ走査からやり直す。
- `config.h` で固定 IP を指定すれば DHCP も省ける。
- 時計を合わせない（NTP を使わない）。日時はサーバーが決める。
- CPU は 240MHz のまま。下げると TLS の計算が延び、その分だけ無線が長く動くので、速く終えて眠る方が得になる。
- 記録には本体が決めた ID（UUID）を付ける。通信が途中で切れて送り直しても二重に記録されないので、失敗したら迷わず送り直せる（最大 3 回。4xx は送り直しても変わらないので諦める）。

## HTTPS

LifeHub の証明書（Vercel が Let's Encrypt で発行する）をルート証明書で検証する。`root_ca.h` に ISRG Root X1（RSA）と X2（ECDSA）を入れてある。証明書の発行元が変わったら、ここを差し替える。本体は時計を持たないので、証明書の有効期限は検証しない（Arduino-ESP32 の mbedTLS は、そもそも日時の検証をしない設定になっている）。

## ファイル

| ファイル | 内容 |
|---|---|
| `lemon-record-button.ino` | ボタンの読み取り（押した回数の数え上げと取り消し）とライトスリープ |
| `screen.cpp` / `screen.h` | 液晶とバックライトの電源、アイコンの描画 |
| `icons.h` | 画面に出すアイコン（`pnpm icons:generate` が生成する） |
| `record.cpp` / `record.h` | Wi-Fi の接続と、記録投入用エンドポイントへの送信 |
| `root_ca.h` | HTTPS の検証に使うルート証明書 |
| `config.example.h` | 設定のひな形（`config.h` に写して使う） |
| `sketch.yaml` | arduino-cli のビルド設定（ボードとライブラリの版） |
